# IG 自動排程發文：技術方案

> **11/3 更新：罐子決定不用 Metricool。** 發文全部走 B（IG 官方 API＋run_schedule.py＋GitHub Actions），下面比較表和 A 路線的內容只留作紀錄。

> 程式設計部 · 2026-11-02 · 查證來源：Meta 官方 [Content Publishing 文件](https://developers.facebook.com/docs/instagram-platform/content-publishing)、[Instagram Login 版](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing)

## 結論

**可以做到「罐子每週只按一次核准，之後全自動發」，而且全程免費。** 有兩條路：

| | A. Metricool（已連線） | B. 自建：IG 官方 API + 免費排程 |
|---|---|---|
| 罐子的一次性設定 | 在 Metricool 連結 IG 帳號（約 5 分鐘） | 建 Meta 開發者帳號與 App、授權一次（約 20～30 分鐘，Claude 給逐步截圖說明） |
| 每週核准 | Metricool 手機 App 或網頁按「核准」 | 在討論串按一次決定卡 |
| 費用 | 免費方案有排程數量與功能上限（需實測確認是否夠用） | 0 元 |
| 能自動發 | 圖片、輪播、Reels（官方說明支援） | 圖片、輪播、Reels、限動 |
| 風險 | 免費方案限制可能改變；第三方平台 | token 每 60 天要延長（排程自動做）；Meta 改 API 時要跟著改 |

**建議（11/2 更新）：罐仔直接走 B（IG 官方 API）。** 原因：查過罐子的 Metricool 帳號，目前只有被被（catbeibei.ai，brandId 7406028）一個品牌；免費版每月 20 則是整個帳號共用，被被每週約 4 則就用掉大半，而且免費版能不能再加第二個品牌也要確認（加品牌若要付費，會先問罐子）。被被的品牌**禁止**拿來發罐仔，已寫進 `brands.json` 與 `route.py`。

`route.py` 每次發文前決定路線：有 IG token → IG API；否則只有在罐仔有自己的 Metricool 品牌、且本月帳號總數 < 20 時才走 Metricool；都不行就 HOLD 不排並回報。

## 自動化流程（兩條路共通）

1. **每週三**：內容部 Claude 寫好下週貼文 → 用 `animator`／`cards` 產出 MP4 與 PNG → 自動檢查（尺寸、字數、Hashtag 數）。
2. **送審**：A 路線：Claude 呼叫 Metricool `createScheduledPostForReview`，罐子手機收到通知；B 路線：在討論串貼出一張決定卡（預覽圖＋文案＋發文時間），選項「全部核准／退回修改」。
3. **罐子按一次核准**（每週約 5 分鐘）。
4. **到點自動發**：A 由 Metricool 發；B 由 GitHub Actions 排程（免費）在指定時間執行 `ig_publish.py`。
5. **發完回報**：隔天抓成效數據交給財務數據部。

## B 路線技術細節

**帳號條件**
- IG 必須是**專業帳號（商業或創作者）**，免費，在 IG 設定裡切換即可。
- 使用「Instagram Login」版 API **不需要 Facebook 粉專**。

**權限（scope）**：`instagram_business_basic`、`instagram_business_content_publish`、`instagram_business_manage_comments`（留言程式）、`instagram_business_manage_insights`（數據部讀成效）── 四個一次勾好，罐子只授權一次

**發文流程（3 個 API 呼叫）**
1. `POST /<IG_ID>/media` 建立媒體容器：單張圖用 `image_url`；Reels 用 `media_type=REELS` ＋ `video_url`；輪播先逐張建立 `is_carousel_item=true` 的子容器，再建 `media_type=CAROUSEL` 的母容器。
2. `GET /<容器ID>?fields=status_code` 等到 `FINISHED`（影片需要處理時間）。
3. `POST /<IG_ID>/media_publish`，帶 `creation_id` 正式發布。

**限制**
- 每 24 小時最多 **100 則** API 發文（輪播算 1 則；舊版文件寫 50，我們一天 1 則遠低於上限）。可用 `content_publishing_limit` 查詢。
- 輪播上限：官方新版寫 20 張、舊版 10 張，程式保守用 10 張。
- **媒體必須放在公開網址**，IG 伺服器會自己來抓；圖片只收 **JPEG**（程式會自動把 PNG 轉 JPEG）。
- 容器 24 小時內沒發布會過期，所以容器在發文當下才建立。

**媒體放哪裡（免費）**：一個公開的 GitHub repo（反正內容本來就要公開發），用 raw 網址給 IG 抓；或 Cloudflare R2 免費額度。建議 GitHub，因為排程也在 GitHub Actions，同一處管理。

**token**：長效 token 有效約 60 天，可用 `refresh_access_token` 延長（依我所知的規則，官方頁面未寫明，實際授權時確認）。排程每 50 天自動延長一次。

**要不要 App 審查**：只發到自己的帳號時，把罐子的 IG 加為 App 的測試者／管理員，在開發模式下就能用，通常不需要送審（官方頁面未寫明，授權時實測確認）。

## 罐子要做的一次性步驟（選 B 時才需要）

1. IG 切換成專業帳號（若還不是）。
2. 到 developers.facebook.com 用自己的 FB 帳號註冊開發者（免費）。
3. 建立 App → 加入「Instagram」產品 → 把自己的 IG 加為測試者並在 IG 接受邀請。
4. 授權時一併勾選 `instagram_business_manage_comments`（留言程式）與 `instagram_business_manage_insights`（數據部），只要授權一次。
   token 統一存在 `數據部/.ig_token`（權限 600），發文、留言、數據三支程式都讀這裡；續期只由數據部每週一的排程做，避免重複續期。
5. 按一次「產生 token」授權，把 token 貼到 GitHub repo 的 Secrets（Claude 會給每一步的連結）。

之後罐子只剩每週按一次核准。

## 發文前三道關卡（全部自動，任何一關沒過就不發）

1. **官網重查**（`程式部/factcheck/`）：重新抓官網比對回饋率、上限、活動日期；「發文前提」沒打勾也擋。
2. **法務部合規檢查**（`法務部/compliance_check.py`＋`rules.json`，每次執行重新載入，法務部每月 1 日更新規則）：禁語、數字揭露、業配 #廣告、推薦連結揭露。FAIL 不發。
3. **文案檢查**（/ig-human、/ig-caption）。

Metricool 路線同樣在送排程前跑這三關。Meta App 上線時，隱私權政策網址使用法務部提供的頁面。

## 每日自動發文（11/3 新增）
- `run_schedule.py`：每 10 分鐘跑一次。依 `內容部/規格/第1-2週.json` 的 date 欄，到時間、還沒發、沒超過 2 小時的貼文才會發，一次一篇。超過 2 小時不補發，寫進 `待處理.md` 等人決定。已發的記在 `publish_ledger.json`。
- 執行環境：`github_actions/publish.yml`（GitHub Actions，免費）。媒體放在 GitHub Pages `…/canzai/media/<資料夾>/`，給 IG API 抓。
- 解鎖：`brands.json` 的 `schedule_enabled` 預設 false。要等兩件事都完成才改：① verify_auth.py 全綠 ② 罐子核准封面一覽。
- 手動發（測試文、00 自介）：`python3 ig_publish.py post <資料夾> --base-url <公開網址> --manual`。排程沒解鎖也能發，帳號核對和三道關卡照跑。發完跑 `python3 run_schedule.py --mark 00 --media-id <ID>`，排程就不會重發。
- 每次發文前都會核對 token 的帳號是不是 @canzai_money，不是就不發。
- 置頂：API 不能置頂，00 發完會寫進 待處理.md 提醒手動置頂。

## 不綁 FB 粉專（11/3 罐子決定「不用FB」）
程式部所有程式本來就走「Instagram API with Instagram Login」（graph.instagram.com，IG 開頭的使用者長效 token），完全沒有用到 graph.facebook.com，所以這次不用改。
- 這條路線做得到：發文（圖、輪播、Reels、限動）、讀留言、回覆和隱藏留言、私訊（instagram_business_manage_messages）、帳號與貼文洞察。
- 只有 FB 粉專路線做得到的（依 Meta 文件，啟用前會再確認一次）：
  1. Hashtag 搜尋（查某個 Hashtag 的熱門貼文）→ 情報部改用網頁搜尋和人工瀏覽
  2. Business Discovery（用 API 看其他帳號的公開數據，例如競品貼文的讚數）→ 情報部改用人工看
  3. 廣告投放、加強推廣的 API（Marketing API）→ 要下廣告時可以在 IG App 裡直接推廣，不需要 API
  4. 商品標籤（Instagram 購物）→ 罐仔不賣實體商品，用不到
- 結論：目前的計畫都不受影響。

## GitHub Actions 一覽（canzai repo，11/3）
| workflow | 時間（台灣） | 做什麼 |
|---|---|---|
| `publish.yml` | 每 10 分鐘 | run_schedule.py 到時間就發文 |
| `ig_fetch.yml` | 每天 08:13；週一多跑一次週區間 | 數據部 ig_fetch.py，輸出 commit 到 `data/ig/` |
| `refresh_token.yml` | 每週一 07:07 | 續期 IG 長效 token，寫回 secret（改由程式部負責，原本是數據部） |

罐子要在 repo 設定的 secrets：`IG_TOKEN`、`IG_USER_ID`、`GH_SECRETS_PAT`（fine-grained token，只授權 canzai repo，權限 Secrets 讀寫）。任何 workflow 失敗，GitHub 都會寄信給罐子。

## 防重複（11/5，罐子把 Metricool 連上 @canzai_money 當數據與手動備援）
發文前先查 IG 最近 25 則貼文：48 小時內只要有文案開頭相同的（去掉空白和 Hashtag 後比對前 40 字），就不發，結束碼 4。run_schedule 收到結束碼 4 會記成「已在 IG（手動或 Metricool）」，不會再重試，並寫進 待處理.md。API 查不到時不擋（只印提醒）。
